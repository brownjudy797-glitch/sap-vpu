# SAP-VPU Work Records - 2026-07-24 - Sparse FPGA policy power

## Objective

Measure dense and selected TinyViT K=128 FC2 sparsity policies with the same
current `sap_vpu_subsystem` FPGA netlist, routed checkpoint, clock, fixture, and
iteration count.

## Autonomous K512 Accumulation

- Added custom-0 `VTSTREAM` (`funct7=0x25`). `rs1` points to input, weight,
  output, and control words; control bit 8 enables an optional metadata-base word.
- The subsystem loops over K8 tiles, reuses the existing 2x2x8 scheduler,
  accumulates four INT32 results, and writes only the final output tile.
- The captured dense 2x512x2 fixture passes with exact outputs and
  `512 VDOT / 516 reads / 4 writes`, versus `512 / 512 / 256` for the previous
  partial-write path. Two consecutive runs pass with `1024 / 1032 / 8`.
- Existing K512 dense, sparse, and four-pair policy regressions remain unchanged.
- Packed metadata now carries four K8 blocks per word. Both tracked 6.25% sparse
  policies pass at `480 VDOT / 496 payload reads / 517 total reads / 4 writes`.
  The 16 metadata reads offset the 16 payload reads saved, so this case supports
  compute and writeback reduction but not a total-read claim.
- No new FPGA or ASIC metric is claimed from this RTL-only result.
