# SAP-VPU Work Records - 2026-07-06 - Framework figure

- Added a first SAP-VPU framework SVG covering the TinyViT software policy,
  CV32E40X/CV-X-IF attachment, SAP-VPU policy state, packed dot-product
  datapath, counters, and RAM-tile evidence path.
- Added `docs/SAP_VPU_FRAMEWORK.md` as the documentation entry point for the
  framework figure and linked it from the project document index.
- Added an `adaptive_unstructured` TinyViT smoke row using INT4 bitmap `0x55`
  to cover non-contiguous sparse policy evidence, with exact result, counter,
  traffic, and CSV summary checks.
- Expanded low-bit and ablation TinyViT policy rows to a 2-token x
  2-output-channel macro-tile, aligning their VDOT count and observed RAM tile
  traffic with the dense row.
- Added a `dense_reuse` TinyViT row that reuses loaded tokens and weights within
  each block, preserving dense output and VDOT count while reducing observed RAM
  tile reads from 384 to 256.
- Added an `adaptive_reuse` TinyViT row with INT4 bitmap sparse policy and
  block-local operand/weight reuse, preserving the adaptive output, skip count,
  and VDOT count while reducing observed RAM tile reads from 384 to 256.
- Expanded the TinyViT smoke tile from four to eight blocks, increasing each
  kernel to 512 VDOT ops and updating the testbench, CSV summary, and smoke
  record to the new 7168-read RAM tile assertion.
- Added the first standalone SAP-VPU FPGA evidence flow: `make fpga-vpu-synth`
  runs Vivado synthesis/place/route/report for `sap_vpu_core`, and
  `make fpga-vpu-summary` summarizes the generated utilization, timing, and
  power report boundary.
- Added a TSMC28-only Synopsys Design Compiler flow for standalone
  `sap_vpu_core`: `make dc-vpu-synth` targets the local TSMC28 `.db` library,
  and `make dc-vpu-summary` summarizes area, timing slack, and vectorless power
  without using an open PDK library. The wrapper intentionally does not source
  the local Synopsys environment file by default so unrelated open-library
  variables do not enter the ASIC flow.
- Reran the TSMC28 DC flow after reboot with the local Synopsys license server.
  DC L-2016.03-SP1 successfully checked out a license, analyzed the SAP-VPU RTL,
  loaded the TSMC28 libraries, and reached mapping, but crashed with an internal
  system error during Pass 1 Mapping for `compile_ultra`, ordinary `compile`,
  `compile -exact_map`, an alternate `tt1v25c` corner, and `USE_DW=0`.
  Therefore no TSMC28 area/timing/power number from this run is paper-citable.
  The flow now exposes conservative `MAP_EFFORT`, `AREA_EFFORT`, `EXACT_MAP`,
  and `USE_DW` knobs for later reruns or a newer DC installation.
