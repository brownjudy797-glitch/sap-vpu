# SAP-VPU Work Records - 2026-07-14 - Gate-Level SAIF Investigation

## Findings

- The existing TSMC28 10 ns DDC policy matrix remains reproducible, but its
  RTL-originated SAIF has 2,216 `PWR-452` unmatched objects.
- The emitted `vpu_core_sliced_10ns_nopower` Verilog contains
  `SYNOPSYS_UNCONNECTED_1/2` in a DesignWare 32-bit adder `SUM` connection.
  The markers feed `rsp_data_o[19]` and `rsp_data_o[15]`, producing unknown
  response data in gate simulation.
- A separate 10 ns `COMPILE_ULTRA=0` DC export has no
  `SYNOPSYS_UNCONNECTED` markers. VCS-MX O-2018.09-SP2 passes
  `GATE_SMOKE_PASS` with the TSMC28 Verilog model at 275.044 ns.
- Dumping every standard-cell model scope created `PWR-452` mismatches. Limiting
  VCD capture to the DUT top level and using `vcd2saif -instance
  sap_vpu_core_gate_tb/dut` produces a gate SAIF that DC annotates without
  `PWR-452`.
- The clean gate smoke reports 617.6453 uW dynamic power and 72.7307 uW
  leakage at TSMC28 `tt0p9v85c`, 10 ns. It is not a policy matrix or full-SoC
  power result.
- The regenerated nine-policy gate matrix has 18,295,784 ps activity windows
  and zero `PWR-452` objects in every row. Dynamic power spans 645.8332 uW to
  665.3819 uW, a 2.99% range relative to dense INT8.
- DC L-2016.03-SP1 remains intermittently unstable during startup or mapping
  under WSL. Failed runs produce no reusable DDC or paper evidence.

## Action

- Added `make dc-vpu-gate-netlist-check` to reject emitted Verilog containing
  `SYNOPSYS_UNCONNECTED` before any gate-level VCD/SAIF claim.
- Added `dc-vpu-gate-synth`, `dc-vpu-gate-sim`, and
  `dc-vpu-gate-saif-power` targets. The SAIF target requires a clean existing
  DDC, a passing VCS-MX gate smoke, and zero `PWR-452` annotation output.
- Moved `dc-vpu-policy-power-matrix` to the clean VCS-MX gate netlist path and
  made nonzero `PWR-452` a hard failure. The resulting matrix is valid
  gate-level activity evidence but remains a standalone fixed-window result.

## TinyViT Fixture Entry

  `tinyvit_mlp2` projection. It validates symmetric INT8 values, zero-points,
  positive scale metadata, and source provenance before materializing assembler
  and SystemVerilog golden includes.
- The default fixture reproduces the existing packed words and `1120` integer
  accumulated output. `make tinyvit-smoke` passes with that generated input.
- The testbench ROM image is now parameterized so alternative fixture builds
  can load their own generated hex image rather than silently executing the
  default one. Checkpoint-derived data remains pending; this is input plumbing,
  not a full TinyViT or accuracy claim.

  `2` generated an accumulated golden of `1168` and passed the same SoC smoke.
