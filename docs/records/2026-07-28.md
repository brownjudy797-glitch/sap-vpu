## Arbitration Repair

The first SoC simulation completed all eight operand DMA reads but deadlocked
at the first output load. The younger CPU load held the shared RAM request while
the older `VTSTORE` needed a VPU DMA grant, and the fixed CPU-priority arbiter
prevented either instruction from retiring.

`corev_min_soc` now grants a pending VPU DMA request before a CPU data request.
The VPU transaction is bounded by the active custom instruction, so a separate
fairness state machine is not required for the current one-in-flight contract.
The model-derived simulation and original tiled-GEMM DMA smoke both pass after
the repair; SoC lint also passes.

## Boundary

This result proves that image-derived, checkpoint-traceable transformer data
can traverse the current CPU-to-VPU software and hardware path on a real FPGA
for the complete K=192 FC1 input dimension. The board result covers two tokens
and two output channels; the separate gate-SAIF matrix covers all 768 FC1
outputs for two tokens. Neither result claims bias, GELU, later layers,
external-memory loading, or end-to-end DeiT inference. The default-activity
board power estimate is not a paper power result. The reported 35.81/30.83/
31.37 us intervals are a controlled kernel measurement, not image-to-class
application latency.
