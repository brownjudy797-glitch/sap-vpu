## Baseline Boundary

- The checked TinyViT fixture is a fixed two-token INT8 MLP projection. It is
  an instruction-path and counter sanity test, not a checkpoint import,
  end-to-end model deployment, accuracy result, FPGA result, or ASIC result.
- The canonical reference values and evidence boundary are recorded in
  `docs/baseline/VDOT_REFERENCE_V0.md`.

## Phase 1 Mapping Contract

- The fixture generator now emits a machine-readable layer-to-VDOT mapping.
  The current two-token 4 -> 4 -> 2 MLP maps to 8 FC1 VDOTs and 4 FC2 VDOTs
  per iteration, or 192 VDOTs across the 16-round smoke.
- The current `MAC_ACTIVE` counter increments once per completed VDOT. The
  mapping also records the corresponding 768 scalar products so future tables
  do not conflate vector operations with scalar multiplications.
- The contract explicitly states the present boundary: CPU loads packed operand
  words from RAM and issues VDOT. A bounded scratchpad/tiled engine is only a
  specified next implementation step, not current hardware behavior.
- Added a dependency-free tiled-GEMM executable reference. It checks the
  tracked MLP result plus M/N/K tails, row-major byte addresses, signed 32-bit
  accumulation, and saturating INT8 requantization before RTL integration.
- Added the first bounded tiled-GEMM RTL scheduler. It stores two packed input
  and two packed weight words, drives the existing VPU command interface, and
  returns indexed results for full 2x2x4 and 1x1x3 tail tiles. Direct RAM/DMA
  access remains outside this slice.
- Added `sap_vpu_subsystem` and the `VTLOAD`, `VTSTART`, and `VTREAD` custom
  operations. A CV32E40X bare-metal smoke now loads, runs, and reads full and
  K-tail tiles through CV-X-IF; legacy VPU and TinyViT SoC smokes still pass.
- Updated TinyViT SAIF hierarchy from `vpu_i` to `vpu_i/core_i` because the
  standalone VPU core is now nested under the subsystem in the SoC.
