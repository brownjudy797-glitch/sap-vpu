# SAP-VPU Model Mapping Contract

## Scope

This Phase 1 contract describes the first model layer that SAP-VPU can execute
through its existing CPU-issued VDOT path. It freezes data layout and command
accounting before a scratchpad-fed tiled engine changes the hardware.

## Current Artifact

The input is `sw/baremetal/fixtures/tinyvit_mlp2_smoke.json`:

- `input_tokens[M][K]`: M=2, K=4, signed INT8.
- `fc1_weights[H][K]`: H=4, signed INT8, followed by scalar ReLU.
- `fc2_weights[N][H]`: N=2, signed INT8.
- Quantization is symmetric INT8 with zero-points fixed at zero.

An actual export must set `provenance.kind` to `checkpoint`, provide the model
and layer identifiers, and include the checkpoint SHA-256. The tracked smoke
fixture remains a deterministic input, not a model checkpoint.

## Layout and Command Stream

- Matrices are row-major. Each VDOT source word packs four signed INT8 values
  in little-endian lane order.
- The CPU loads an input or hidden word and a weight word from RAM, then issues
  `VSETPREC INT8`, `VSETSPARSE_BMP 0x0f`, `VSETLANE 4`, and `VDOT`.
- FC1 performs M*H=8 VDOTs and applies ReLU in scalar software. FC2 performs
  M*N=4 VDOTs. One inference round therefore has 12 VDOTs and 48 scalar
  products; the 16-round smoke has 192 VDOTs and 768 scalar products.
- `work/tinyvit/fixture/tinyvit_mlp2_vdot_mapping.json`, generated by
  `make tinyvit-fixture`, is the executable copy of this accounting.

`MAC_ACTIVE` currently increments once per completed VDOT. It must be labeled
as a VDOT count in future reports; scalar-product totals come from the mapping.

## Bounded Tiled-Engine Contract

The next RTL block must preserve the above numerical result while changing only
data movement:

1. Accept row-major signed INT8 M, N, K tensor descriptors and byte strides.
2. Stage one bounded M=2, N=2, K=4 tile in a private scratchpad.
3. Accumulate signed products in 32 bits, apply ReLU only between FC1 and FC2,
   and expose a valid-element count for M/N/K tails.
4. Return results through the existing command response path; no coherent
   cache, autonomous DRAM, or new general-purpose RVV interface is implied.

Before RTL integration, a reference test must cover tile addresses, M/N/K
tails, 32-bit accumulation, and quantized output against a scalar golden.

## Reproduction

```sh
make tinyvit-fixture-check
make tinyvit-fixture
make tinyvit-smoke
```

The first command validates the generator and mapping counts. The final command
checks the generated model data through the CV32E40X plus CV-X-IF plus SAP-VPU
SoC path.
